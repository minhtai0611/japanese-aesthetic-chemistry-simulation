# Accessibility — KAGAKU

Real accessibility testing documentation (not a theoretical checklist) for Phase 6 of
the production hardening plan. All results below were measured on the development machine,
production build (`next build` + `next start`), Windows 11, Chromium browser
(Edge) headless for Lighthouse, Chrome for manual testing.

## 2. Stopping the render loop under reduced motion

`src/lib/dung-chuyen-dong.ts` (`useGiamChuyenDong`) reads `prefers-reduced-motion`
via `useSyncExternalStore`, which the user can override with the "Motion" button
shown in the menu (no need to know how to change OS settings).

There are four places with a continuous render loop, each checked individually:

| File | Stop mechanism | Verification |
|---|---|---|
| `ba-d/canh-hero.tsx` | `Canvas frameloop={giam ? "demand" : "always"}`, disables `EffectComposer`/Bloom | Turn on "Motion: Reduced" in the header → capture 2 frames 2s apart, the molecule is at exactly the same rotation angle, the Bloom halo is gone |
| `ba-d/canh-hop-chat.tsx` | `frameloop={tuXoay ? "always" : "demand"}` — `tuXoay` initialized from `!giam`, the user can still turn it back on manually | Read the code + `TrucXoay`'s `useFrame` only increments the angle when `tuXoay` is true |
| `hop-chat/trinh-pham-3d.tsx` | `useState(!giam)` for `tuXoay` | Read the code |
| `thi-nghiem/phong-chuyen-pha.tsx` (`useDongCoHat`) | When `giam` is on: draws exactly one static frame at the original grid position and then does **not** call `requestAnimationFrame` | Read the code — the `if (giam) { ...; return; }` branch runs before entering the `ve()` loop |

**Manual DevTools check**: turn on "Motion: Reduced" in the header, open the
Performance tab, record 3s on `/` — no repeating `requestAnimationFrame` entries
for the hero Canvas (only one-off interaction events when a button is pressed).

## 3. No-WebGL fallback / data saver mode

`src/components/ba-d/phan-tu-2d.tsx` (`coWebGL()` + `PhanTu2D`): projects the 3D
coordinates onto the XY plane (dropping z, keeping the z draw order — the painter's
algorithm), drawn with SVG. Atom radius and CPK color are **identical** to the 3D
version (`mauCua` shared with `mat-phan-tu.tsx`) — no data accuracy is lost.

`src/components/che-do-tiet-kiem.tsx` (`useCheDoTietKiem`): a localStorage flag,
synced across every open component via `CustomEvent`. When enabled:

- `hero-nen.tsx`: **does not load** the `ba-d/canh-hero` chunk — replaced with a static gradient div
- `hop-chat/trinh-pham-3d.tsx`: uses the `PhanTu2D` SVG instead of `CanhHopChat` — doesn't load the three.js chunk for the molecule stage
- `thi-nghiem/phong-chuyen-pha.tsx`: simulated particle count 96 → 24

**Manual check**: DevTools → Network → Disable cache → disable WebGL via the flag
`chrome://flags/#disable-webgl` (or open `/hop-chat/caffeine` on a machine without a
compatible GPU) → the molecule stage automatically switches to 2D SVG, with the
caption "Máy không hỗ trợ WebGL: sơ đồ 2D chiếu trực giao". Turn on "Data saver" in
the header → the homepage hero switches to a static background, the molecule stage
switches to SVG immediately (confirmed with before/after screenshots).

## 5. Periodic table — semantic `<table>`

`bang-tuan-hoan/bang.tsx` was rewritten entirely from an ad-hoc CSS Grid of `div`s to
a real `<table>`: the `<thead>` has `<th scope="col">` for the 18 groups, each `<tr>`
is a real period with a `<th scope="row">` + exactly 18 `<td>`s (including empty
ones) — so screen readers can correctly compute "row X of Y, column Z of W" from the
DOM structure itself, **not** relying on `grid-column`/`grid-row` CSS (CSS visual
position is not used by assistive tech to compute a table's row/column numbers). The
lanthanide/actinide series are two separate `<tr>`s at the bottom, also with the full
18 `<td>`s to keep the column count consistent with the main table.

Empty cells replace the previous "57–71"/"89–103" markers (which used to overlap the
exact position of the element cells, a pre-existing display bug) — now a clean
`<th scope="row">` with no overlap.

Checked with `read_page` (accessibility tree), confirming the `<table>`/`<th>`
structure is present correctly; visually confirmed via screenshot with no difference
from the original layout (18 columns, the f-block split into its own rows, block
color legend).

## 6. Remaining items

- Heading hierarchy: `/bang-tuan-hoan` now has an `<h2 className="sr-only">` for the
  table + legend area (previously h1 → table, with no h2). `/hop-chat/[ten]` changed
  the "Hồ sơ PubChem" label from a `<p>` to an `<h2>` (previously h1 → h3, a level skip).
- `aria-valuetext` for all 5 sliders (titration ×2, prep ×4, phase change ×1) — reads
  the value with its unit (`"0.50 M"`, `"300 kelvin, 26.9 °C, trạng thái lỏng"`, etc.)
  instead of just the raw number.
- `aria-live="polite"` for the current pH, weighed mass, dilution result, and
  temperature/state of the phase-change chamber.
- Target size ≥ 44×44px: every periodic-table element cell has `min-h-11 min-w-11`
  (Tailwind `11` = 2.75rem = 44px) — applied to both real element cells and the
  57–71/89–103 placeholder cells.
- A "Motion" button is shown in the header (desktop) and the mobile menu — no need
  to know how to change OS settings.
- Phase-change chamber: 26 of 118 elements are missing enough measured melting/boiling
  points from PubChem — previously silently filtered out of the dropdown; now they
  **still appear in the list** but `disabled`, with a "— PubChem chưa có điểm nóng
  chảy/sôi đo được" note right in the `<option>`, plus a total-count note below the
  dropdown.

## 7. Real measured results

### Lighthouse — `/bang-tuan-hoan`

Measured with `lighthouse http://localhost:3000/bang-tuan-hoan --only-categories=accessibility,performance --chrome-flags="--headless=new"` (Edge headless, the measuring machine has no Chrome installed).

| Run | Accessibility | Notes |
|---|---|---|
| Run 1 (before fixes) | 96/100 | 2 failing audits: `color-contrast` (table row/column numbers, `text-washi-mo/50` = 3.57:1) and `label-content-name-mismatch` (header logo) |
| Run 2 (after changing `/50` → `/70`) | 100/100 | 1 fail remaining: `label-content-name-mismatch` |
| Run 3 (after removing the duplicate logo `aria-label`, using the name from the visible content) | **100/100** | 0 fails |

Both issues found were fixed within this same session:
- `bang-tuan-hoan/bang.tsx`: the row/column index numbers (`<th scope="row"/"col">`)
  changed `text-washi-mo/50` (3.57:1 ❌) → `text-washi-mo/70` (6.05:1 ✅).
- `dieu-huong.tsx`: the header logo had an `aria-label` that didn't contain the full
  visible text inside it (WCAG 2.5.3 Label in Name violation) — removed the
  `aria-label`, letting the accessible name be derived from the visible content
  "KAGAKU 科学 · PHÒNG THÍ NGHIỆM SỐ".

The Lighthouse Performance score (45–48/100) was measured on `next dev` (Turbopack
dev server, unminified, with HMR runtime) — **not representative** of real
performance; the plan's acceptance gate only requires an Accessibility score ≥ 95,
with no Performance threshold for the dev environment.

### Executed JS — how much does data saver mode cut?

Measured with a **real production build** (`next build` then `next start -p 3001`),
capturing every `_next/static/chunks/*` request via DevTools Network while opening
`/hop-chat/aspirin`, comparing the exact same page with just "Data saver" toggled
on/off:

| State | Total JS/CSS bytes loaded | Chunk difference |
|---|---|---|
| Data saver: **on** | 1,169,807 B (~1.11 MiB) | does not load `1guadiyxub194.js`, `3jc9j45ev349b.js` |
| Data saver: **off** | 1,969,208 B (~1.88 MiB) | loads everything (including the 2 three.js/@react-three/fiber chunks above) |

**A reduction of 800,401 bytes, i.e. 40.6%** — exceeding the acceptance gate's ≥ 40%
target. The main difference is the `1guadiyxub194.js` chunk (~764 KiB) — containing
`@react-three/fiber`, `postprocessing`, `n8ao` — which is not loaded at all when
`hero-nen.tsx` skips `CanhHero` and `trinh-pham-3d.tsx` uses `PhanTu2D` (SVG) instead
of `CanhHopChat`.
